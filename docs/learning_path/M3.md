## 一、M3 要做什么（一句话）

**让系统能管理"训练计划"**：把动作组织成模板（如 A/B 分化），再按日期生成当日计划。

M2 有了动作库（字典），M3 在此基础上加两层：
- **模板（Template）**：一组固定动作组合，绑定某个阶段（如"推日模板"= 卧推+推举+臂屈伸）
- **当日计划（Plan）**：某个训练日的动作清单，从模板选/手动加，每动作带计划重量/组数/次数

M3 只做**计划**，不做训练记录（M4 的事）。M3 的目标是：训练前能把今天要练什么"排好"。

## 二、核心概念（先理解再动手）

### 2.1 数据层级（M3 新增两张"子表"）

```
阶段 Phase ─┬─ 模板 Template ──── 模板项 TemplateItem（模板里的一个动作）
            │
            └─ 当日计划 Plan ──── 计划项 PlanItem（计划里的一个动作）
```

- 模板和计划都挂在**阶段**下面（`phase_id`）
- 模板项/计划项都引用**动作库**（`exercise_id`）
- 模板是"可复用的配方"，计划是"某一天的具体安排"

### 2.2 为什么模板和计划分开？

| | 模板（Template） | 当日计划（Plan） |
|---|---|---|
| 性质 | 可复用的配方 | 某一天的安排 |
| 例子 | "A分化"（周一用） | 2026-08-08 的训练 |
| 生命周期 | 长期存在 | 一天一条 |
| 和阶段关系 | 一个阶段多个模板 | 一个阶段多天计划 |

建计划时**从模板复制**动作，复制后独立（改计划不影响模板，改模板不影响已有计划）。
这避免了"昨天改模板，前天计划也变了"的连锁反应。

### 2.3 计划项的"三个值"哪来的？

计划项里有 `plan_sets` / `plan_reps` / `plan_weight`：
- 从模板复制时 → 继承模板项的设置（模板项没写就用动作库默认值）
- 手动添加时 → 直接用动作库默认值
- 都支持人工调整（计划页里改）

### 2.4 归档阶段不可建计划

M2 已实现"归档 = 只读"。M3 延续：归档阶段的模板/计划页应提示"已归档"，
不能新增计划（防修改历史）。

## 三、M3 要做什么（分步）

### 第 1 步：模板 CRUD（templates + template_items）

文件：`src/handlers/plan.rs`（新建）

| 路由 | 方法 | 功能 |
|------|------|------|
| `/phases/{phase_id}/templates` | GET | 模板列表（某阶段下） |
| `/phases/{phase_id}/templates/new` | GET | 新建模板表单 |
| `/phases/{phase_id}/templates` | POST | 创建模板（名称 + 选动作） |
| `/templates/{id}/edit` | GET | 编辑模板表单 |
| `/templates/{id}/edit` | POST | 更新模板 |
| `/templates/{id}/delete` | POST | 删除模板（连同模板项） |

要点：
- 新建模板时，动作列表从动作库选（多选 → 每个选中的动作生成一个 `template_items` 行）
- 删除模板 = 先删 `template_items`（子表）再删 `templates`（父表）——**先子后父**
- 模板名在同一阶段下可重复吗？——可以（如两个都叫"A"），模板按 id 区分

#### ⚠️ `sort_order` 双字段分工（详见 `docs/todo.md` §1.1 / §2.1）

| 字段 | 状态 | 用途 |
|------|------|------|
| `template_items.sort_order` | **实际字段** | `enumerate()` 生成（0,1,2…），决定模板内动作先后，现在就在起作用 |
| `templates.sort_order` | **预留字段**（暂恒为 0） | 模板间排序是**未来待办**（M5/M7），M3 不影响功能 |

**表单多选陷阱**：checkbox 的 `name` 用动作 id（唯一键）、`value="1"`，不能用重复键 `exercise_ids`（serde_urlencoded 是 map 语义，后值覆盖前值）。结构体 `#[serde(flatten)]` 收 `HashMap`。

### 第 2 步：当日计划 CRUD（plans + plan_items）

文件：`src/handlers/plan.rs`（继续）

| 路由 | 方法 | 功能 |
|------|------|------|
| `/phases/{phase_id}/plans` | GET | 计划列表（某阶段下，按日期） |
| `/phases/{phase_id}/plans/new` | GET | 新建计划表单 |
| `/phases/{phase_id}/plans` | POST | 创建计划（选日期 + 选模板或手动选动作） |
| `/plans/{id}` | GET | 计划详情（动作清单 + 计划值） |
| `/plans/{id}/edit` | GET | 编辑计划表单 |
| `/plans/{id}/edit` | POST | 更新计划（增删动作/改值） |
| `/plans/{id}/delete` | POST | 删除计划 |

要点：
- 创建计划时 `date` 字段：默认今天（中国时区），可改
- `UNIQUE(phase_id, date)`：同一阶段同一天只能有一个计划——重复创建会撞唯一约束
  （这是数据库兜底；正常流程是先查当天有没有，有就提示"今天已有计划"）
- 计划详情页 = 动作清单表：动作名 + 计划组数/次数/重量，每行一个 `plan_item`

### 第 3 步：从模板一键生成计划（复制动作）

核心交互：新建计划时选"从模板复制"，把模板项复制成计划项。

```
选模板 → 查出该模板的 template_items → 每个 item 生成一个 plan_item
```

要点：
- 复制时继承 `plan_sets` / `plan_reps`（模板项没写就取动作库默认）
- 复制后是**独立快照**：模板改了不影响这个计划

## 六、M3 常见坑

| 坑 | 解决办法 |
|---|---|
| 删除父表前没删子表 | 先删 `template_items` / `plan_items`，再删 `templates` / `plans`（先子后父） |
| 同一天重复计划 | `UNIQUE(phase_id, date)` 兜底，但应提前查重并提示 |
| 计划值空（None） | 计划项的 sets/reps/weight 是 `Option`，展示时用 `unwrap_or` 或 `if let` |
| 从模板复制时模板项值为空 | 复制时 fallback 到动作库默认值 |
| 归档阶段还能建计划 | 归档阶段应禁止建模板/计划，返回 403 或提示 |
| 数据隔离漏洞 | 所有 SQL 必须带阶段→用户的 JOIN 或 WHERE user_id，不能只按 phase_id 查 |
| 大括号换行 | 项目约定：函数体左大括号换行（Allman 风格） |
| 禁止 unsafe（项目规则） | 任何地方都别用 unsafe |

<summary>点击展开参考答案</summary>

**第 1 题**：模板是**可复用的配方**（长期存在、可反复用），
计划是**某一天的安排**（一次训练日一条）。
模板管"练什么组合"，计划管"哪天练"。

**第 2 题**：因为模板项/计划项用 `template_id` / `plan_id` **引用**父表行。
先删子表（template_items/plan_items）再删父表（templates/plans）——
否则违反外键约束（SQLite 默认不强制，但会留孤儿数据，且设计上必须先子后父）。

**第 3 题**：模板项有值就用**模板项的值**，模板项没值就**用动作库的默认值**
（default_sets / default_reps）兜底。这叫"fallback 链"：计划 ← 模板 ← 动作库。

**第 4 题**：因为有 `UNIQUE(phase_id, date)` **唯一约束**，
保证同一阶段同一天只能有一个计划（一个训练日对应一份安排）。
重复创建会撞唯一约束（插入失败）。

**第 5 题**：因为归档 = **只读**（改字段 archived=1，数据还在但不可修改），
新建计划 = 修改**阶段下的训练安排**（会改变该阶段的数据）。
归档阶段应禁止新增，防止改历史。
