## 二、M0 阶段：先让服务器跑起来（定义完成，待你实现 📝）

**顺序很重要，因为它体现了依赖关系**（下面的文件被上面的文件使用）：

```
第1步  Cargo.toml        先声明依赖，才能用 cargo add 装包
   ↓
第2步  src/config.rs     不依赖任何人，先写它
   ↓
第3步  src/error.rs      不依赖 config，但所有模块都要用它
   ↓
第4步  src/models.rs     用 sqlx 的 FromRow，给表定数据结构
   ↓
第5步  migrations/0001_init.sql  定义 7 张表的字段
   ↓
第6步  src/db.rs         连接数据库 + 自动执行迁移
   ↓
第7步  src/main.rs       把以上全部组装起来，启动服务器 ★ 最高层
```

**为什么是这个顺序？** Rust 编译器按 `main.rs` 里的 `mod` 声明找文件。
`main.rs` 是"指挥塔"，它依赖下面所有模块；所以越底层（config）越先写，
越顶层（main）越后写。

**M0 验收标准**（⏳ 待你实现后逐项勾选，全部打勾才算完成）：
- [ ] `cargo check` 无错误
- [ ] `cargo run` 启动，日志显示"数据库迁移完成"
- [ ] 访问 `http://服务器IP:8080/` 显示"训练记录系统 M0 脚手架运行成功"
- [ ] 理解验证：独立完成 [七、M0 理解验证（填空题）](#七m0-理解验证填空题)，全部答对才算通过

> 【为什么是填空题而不是选择题？】
> 选择题有"答案提示效应"——选项就摆在眼前，眼睛一瞟就能认出正确答案，
> 检验不了真实理解。所以从 M0 起，理解验证统一采用**填空题**：
> 不提供选项，答案必须凭理解自己写出来。
> 这样能真正暴露"以为懂了、其实没懂"的盲区。

## 五、常见坑（写代码时注意）

| 坑 | 解决办法 |
|---|---|
| `port` 变量不存在 | 用 `config.port`，配置在 config.rs 里 |
| `.parse()` 报类型不明确 | 显式标注类型：`let addr: SocketAddr = ...` |
| struct 没实现 Clone | 加 `#[derive(Clone)]` |
| sqlx 查询需要类型标注 | 写 `let n: i64 = ...` |
| 大括号换行 | 项目约定：函数体左大括号换行（Allman 风格） |
| 禁止 unsafe（项目规则） | 测环境变量默认值改用依赖注入：`from_reader(|name| ...)` 传假读取器，勿用 `env::remove_var`（Rust 2024 里是 unsafe） |

> 【说明】完成第 4 节的 3 个练习后，独立完成下面的填空题。

### 第 1 题：AppState 的作用
main.rs 里的 `AppState` 结构体（含 `pool` 和 `config` 两个字段），
通过 `.with_state(state)` 交给 Router 后，它的作用是______。
（提示：想想 handler 处理请求时，它是怎么拿到数据库连接的？）

### 第 2 题：为什么用连接池
db.rs 里用 `SqlitePoolOptions` 建了连接池，而不是每个请求都新建数据库连接，
原因是______。
（提示：想想"连接"是什么资源，同时多个请求来会怎样？）

### 第 3 题：为什么 run_migrations 每次启动都跑，却不会重复建表
db.rs 的 `init_pool` 每次启动都会调用 `run_migrations`，但第二次启动时
并不会重新建表，原因是______。
（提示：想想 sqlx 靠什么记录"哪些迁移已经执行过"？）

### 参考答案（先自己写，再对照）

<details>
<summary>点击展开参考答案</summary>

**第 1 题**：AppState 是"公共储物柜"——装着所有 handler 共享的数据。
每个请求到来时，axum 会 clone 一份 AppState 交给 handler；
handler 通过 `State(state)` 提取器拿到它，再用 `state.pool` 查数据库。
这样数据库连接只需要启动时建一次，所有请求共用。

**第 2 题**：数据库连接是贵资源（文件句柄、内存）。每个请求都新建连接，
性能差（建连慢）且容易冲突；连接池维护一批已打开的连接，
请求来了借一条、用完归还，大家复用，性能好又稳定。
另外 SQLite 单文件同一时刻只能一个写，池大小 5 就够。

**第 3 题**：迁移是幂等的。sqlx 执行完每个迁移后，
会把记录写进数据库里的 `_sqlx_migrations` 表；
下次启动先对比该表，已执行的跳过、没执行的才执行。
所以只有第一次启动真正建表，之后都是"零成本跳过"，
将来新增 `0002_xxx.sql` 时老库也能自动升级，不丢数据。

</details>
